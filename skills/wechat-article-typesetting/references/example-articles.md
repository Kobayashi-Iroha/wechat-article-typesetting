# 案例拆解 · 组件组合模式

不涉及任何真实文章内容——仅抽象出组件序列和设计决策，作为排版参考。

---

## 模式 A：短资讯（500-800 字）

**适用**：费用说明、规则清单、快问快答
**组件序列**：

```
封面卡片（靛蓝满版 + 大标题）
数据表：项目明细（3-4 列）
一句话小结（加粗居中）
子标题：对比项
数据表：前后对比（上下粗线、细线分隔、关键数字红色高亮）
警告卡：为什么有这个差异？
一句话小结（加粗居中）
子标题：怎么做？
清单（绿色对勾 + 加粗关键词）
CTA 尾卡
落款
```

**设计决策**：
- 组件密集但节奏快——表格+一句话小结交替，读者 30 秒扫完
- 核心数字用对比色在表格中突出（如红色高亮差异项）
- 结尾给出明确可操作建议

## 模式 B：深度指南（1500-3000 字）

**适用**：操作手册、决策辅助、攻略
**组件序列**：

```
封面卡片（靛蓝满版 + 眉头标签 + 大标题 + 柠绿装饰条）
章节一：现状分析
  ├─ 子标题 + 正文
  ├─ 数据表（条件 → 结果对照）
  ├─ 警告卡
  └─ 金钱卡组（3 列，不同边框色区分类型）
章节二：路径选择
  ├─ 分支流程图（提问框 → 分叉 → 2-3 条路径卡片）
  ├─ Q&A 块
  ├─ 大字报（柠绿底总结口诀）
  └─ 警告卡
章节三：过渡/后续
  ├─ 子标题
  ├─ 带编号步骤（3 步）
  └─ Q&A 块
CTA 尾卡（5 个药丸服务标签）
落款 + 参考来源
```

**设计决策**：
- 三章节递进：分析 → 选择 → 执行，逻辑链条清晰
- 分支流程图帮助读者「对号入座」到自己的情况
- 大字报放在第二节末尾做记忆锚点
- 组件类型交错排列，避免连续重复同一类型

## 模式 C：问答/判断题（800-1500 字）

**适用**：普法教育、辟谣、自测题
**组件序列**：

```
封面卡片（靛蓝满版 + 提问式标题）
场景 A：情境描述 → 关键信号（红色左边框）/ 提问
场景 B：情境描述 → 关键信号（红色左边框）/ 提问
场景 C：情境描述 → 关键信号（红色左边框）/ 提问
揭晓答案：
  ├─ 快速对照卡（场景 × 答案 × 依据一句话）
  └─ 引导互动：「你答对了几道？」
CTA 尾卡
落款
```

**设计决策**：
- 问答类内容天然适合「情境 → 提问 → 揭晓」三段节奏
- 每个场景提炼一个关键词作为视觉锚点（红色左边框）
- 答案用一句话概括，不堆砌原文——读者扫一眼就够

## 模式 D：金句/观点卡片

**适用**：每日一句、观点传播、品牌宣导
**组件序列**：

```
封面卡片（靛蓝满版 + 大号衬线标题 + 柠绿装饰条）
观点卡片 1（柠绿底 + 靛蓝字 + 衬线体）
观点卡片 2（白底 + 靛蓝左边框 + 衬线体）
观点卡片 3（靛蓝底 + 白字 + 柠绿高亮关键词）
CTA 尾卡
落款
```

**设计决策**：
- 每屏一个观点，极度留白
- 衬线体大标题（32-68px）承担全部视觉重量
- 柠绿/靛蓝/白底交替制造翻页节奏

---

## 组件组合通用规则

1. **每篇文章必须包含**：封面卡片 + 至少一个章节头 + CTA 尾卡
2. **避免连续单调**：同一组件类型不连续使用 3 次以上
3. **色彩呼吸**：两段重色组件之间插入浅色/白底段落
4. **字号三级跳**：标题 26-32px → 子标题 22px → 正文 17px → 辅助 13-15px

## 节奏控制

| 内容密度 | 建议组件间隔 | 典型场景 |
|----------|-------------|----------|
| 高密度 | 每 2-3 段插入一个视觉组件 | 数据说明、清单 |
| 中密度 | 每章节 2-4 个组件 | 指南、手册 |
| 低密度 | 每屏一个组件 + 大量留白 | 金句、观点 |

**判断标准**：在手机上以 375px 宽度连续往下滑——如果在任何一屏上看不到一个有颜色的组件（卡片、左边框、色块、表格），节奏就太单调了。
